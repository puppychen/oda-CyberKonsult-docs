# RFC-001：客戶角色與回應層級簡化

> **TL;DR**：客戶帳號簡化為新手（Free）、一般（Plus）、顧問（Pro）；提示詞只依回應層級選取。新手每日預設 20 次，可由管理後台調整。管理、資料清理與 Maker-Checker 審查流程不變。

## Metadata

| 欄位 | 內容 |
|------|------|
| 日期 | 2026-07-11 |
| 分類 | Major（跨模組、資料 migration、授權與額度） |
| 狀態 | Approved |
| 關聯需求 | US-01-02、US-03-01～04、US-16-01～05 |
| 核准依據 | 使用者於本次對話完成角色矩陣、額度與介面確認後回覆「同意」 |

## 為什麼要改

原本帳號角色與回答模式交叉對應，造成管理、提示詞與使用者選擇過度複雜。此次將方案權限與回答深度直接對齊，保留內部 `mode` 欄位以維持 API 相容，但介面統一稱為「回應層級」。

## 決策

| 帳號角色 | 方案 | 可用回應層級 | 預設 |
|----------|------|--------------|------|
| `basic_user` | 新手（Free） | 新手 | 新手 |
| `user` | 一般（Plus） | 新手、一般 | 一般 |
| `consultant` | 顧問（Pro） | 新手、一般、顧問 | 顧問 |
| `data_cleaner` | 內部角色 | 一般 | 一般 |
| `data_reviewer` | 內部角色 | 一般 | 一般 |
| `admin` | 管理角色 | 新手、一般、顧問 | 一般 |

- `it_user` 併入 `user`，migration 同步清除 refresh token 並遞增 `tokenVersion`。
- 公開註冊固定建立 `basic_user`；管理員仍可指派全部六種有效角色。
- 提示詞每個回應層級只允許一筆啟用版本；既有資料不刪除，多餘版本改為停用。
- 新手每日訊息額度預設 20 次，範圍 1～1000，台北時間每日 00:00 重置。
- Admin 與 Chatbot 沿用現有視覺系統，只調整功能欄位與狀態顯示。

## 資料移轉

| 資料 | 規則 |
|------|------|
| 使用者 | `it_user → user`，舊 Token 全部失效 |
| beginner 提示詞 | 最新啟用非 seed 版本優先，否則 `seed-user-beginner` |
| standard 提示詞 | 最新啟用非 seed 版本優先，否則 `seed-it_user-standard` |
| expert 提示詞 | 最新啟用非 seed 版本優先，否則 `seed-consultant-expert` |
| 其他提示詞 | 保留資料並停用，不刪除 |

## 風險與控制

| 風險 | 控制 |
|------|------|
| 並行請求超過每日額度 | 以條件式 `updateMany` 原子遞增，失敗回 429 |
| 舊 JWT 保留 `it_user` 權限 | migration 遞增 `tokenVersion` 並清除 refresh token |
| 提示詞多筆同時啟用 | PostgreSQL partial unique index 限制每個 mode 一筆 |
| migration 選錯提示詞 | migration 前備份 `users` 與 `prompt_templates`，套用後核對三筆 canonical row |

## 回復方式

程式可回復至前一版本；資料庫回復需使用 migration 前備份還原 `users`、`prompt_templates`，並移除新用量資料表與索引。正式套用 migration 屬 T3 操作，必須另行確認。
