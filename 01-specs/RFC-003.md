# RFC-003：任務命名、快速改名與台灣時間

## TL;DR

新清洗任務建立前必須填寫任務名稱，任務中心在任務 ID 與狀態之間顯示名稱。Admin 可直接在列表修改任何新舊任務名稱；任務時間由 API 明確標記 UTC，Admin 固定以台灣時間（UTC+8）顯示。

## 變更原因

目前任務只能靠 UUID 與狀態辨識，資料量增加後無法快速判斷任務內容。`tasks.created_at` 儲存 UTC 無時區值，但 API 未帶時區，瀏覽器誤判為本地時間，導致台灣介面少顯示 8 小時。

## 核准決策

| 決策 | 核准結果 |
|---|---|
| 新任務名稱 | 建立前必填，去除前後空白後為 1～100 字；允許重複。 |
| 舊任務 | 資料庫維持 `NULL`；未改名前顯示「歷史任務（未命名）」。 |
| 快速改名 | 任務中心採行內編輯；所有任務狀態皆可修改。 |
| 權限 | 只有 Admin 可改名；資料清洗與審核角色維持唯讀。 |
| 併發 | 最後成功儲存者為準；成功後重新取得伺服器資料。 |
| 稽核 | NestJS 記錄 `TASK_NAME_UPDATE`、操作者與任務 ID。 |
| 時間 | FastAPI 將既有無時區時間視為 UTC 並輸出 ISO 8601 offset；Admin 固定以 `Asia/Taipei` 顯示。 |

## API 與資料庫

- `POST /api/v1/clean` 新增必填 `task_name`。
- `PATCH /api/v1/tasks/{taskId}/name` 接受 `{ "task_name": "..." }`，僅 Admin 可呼叫。
- Alembic `012` 新增可空的 `tasks.task_name VARCHAR(100)`；不回填舊資料。
- `TaskResponse` 新增可空 `task_name`；時間欄必須是含 `+00:00` 或 `Z` 的 ISO 8601 字串。

## 完整行為矩陣

| 任務來源 | 任務狀態 | 名稱輸入 | 結果 |
|---|---|---|---|
| 新／舊 | 等待中／處理中 | 1～100 字 | 可儲存。 |
| 新／舊 | 等待中／處理中 | 空白或超過 100 字 | 阻擋並保留編輯狀態。 |
| 新／舊 | 完成／失敗／取消／已入庫 | 1～100 字 | 可儲存。 |
| 新／舊 | 完成／失敗／取消／已入庫 | 空白或超過 100 字 | 阻擋並保留編輯狀態。 |

## 回復方式

降版 `012` 只移除 `tasks.task_name`。改名前後均不影響清洗結果、Maker-Checker、下載、入庫、向量資料或任務狀態。

## 不變範圍

清洗規則、Maker-Checker 權限、下載與入庫流程、任務 UUID 及 Admin 既有視覺風格維持不變。其他環境不由本次本機作業代為執行 migration。
